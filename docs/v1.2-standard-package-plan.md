# Release Signal V1.2 Standard Package Plan

This document records the V1.2 packaging labels and plan-code coexistence rules before billing or trial behavior changes are implemented.

## Product Labels

- Product name: Release Signal
- Base commercial plan label: Standard
- Trial label: Standard Trial
- Full Standard package name: Release Signal Standard
- Full Standard Trial package name: Release Signal Standard Trial
- Internal release label: v1.2

These labels are packaging and display terminology. They do not change product truth, billing enforcement, credits, trial duration, or account creation behavior.

## Plan Codes

- `trial_v1`: legacy/founding/private-beta trial cohort
- `standard_trial_v1`: future V1.2 commercial Standard Trial for newly created organizations only
- `standard_v1`: future paid or manually activated Standard plan

## Coexistence Rules

- Existing `trial_v1` records remain unchanged.
- `standard_trial_v1` is for new V1.2 commercial Standard Trial organizations only after trial initialization is changed in a later scoped branch.
- `standard_v1` is the future paid/manual Standard plan.
- No organization should be migrated from `trial_v1` to `standard_trial_v1`.
- Existing organizations must not be backfilled, reset, or granted replacement trial credits.
- `trial_v1` must remain recognized as a valid legacy trial cohort while those records exist.

## Allowed Future Transitions

- `standard_trial_v1` -> `standard_v1`
- `trial_v1` -> `standard_v1`
- `standard_v1` -> future Pro or Team plans

## Disallowed Without Explicit Future Scope

- `trial_v1` -> `standard_trial_v1`
- `standard_v1` -> `standard_trial_v1`
- resetting trial credits
- backfilling existing organizations
- changing existing trial periods
- silently mutating existing subscriptions, wallets, ledgers, users, or organizations

## Implementation Boundary

This planning branch does not:

- change trial duration
- change credit grants
- change account creation behavior
- change billing or access enforcement
- change `/api/chat`
- change Prisma schema or migrations
- change plan-code assignment behavior
- add payment provider integration
